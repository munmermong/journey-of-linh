Exploring the structure and design of my website

Structure • Design • Accessibility

01. Overall Website Structure

This personal portfolio presents my experiences, learning journey and future aspirations in computing. Rather than a strict hub-and-spoke model where every trip has to pass back through the home page, I built it as a small connected network: all four pages share the same navigation bar, so a visitor can jump directly from any one page to any other without detouring through Home first. The four pages are:

  • Home (index.html) - A short introduction to me and an entry point into the rest of the site.
  • My Past (past.html) - Previous experiences and learning progress with computing.
  • My Future (future.html) - Goals, ambitions and future plans in computing.
  • Comments (comments.html) - This page - a reflection on the site's own structure and design decisions.

Three navigation layers reinforce each other on every page: the sticky top navbar (always visible, even while scrolling), the footer link list (reached after reading a page fully, for visitors who scroll rather than jump), and the "Explore My Journey" timeline sidebar, which links to sections within the current page rather than between pages. 02. Internal Page Structure

All four pages follow the same block order from top to bottom, so once a visitor learns the pattern on one page, every other page reads the same way. The diagram below shows that stacked structure, and the table underneath explains what each block is for.

Element Purpose
Navigation bar Links to the four main pages; stays fixed to the top of the viewport while scrolling (position: sticky).
Cover Introduces each page with a title and subtitle. On the home page the cover is a two-column grid with an overlapping photo; on the sub-pages it's a flex column with small label text above and below the title.
Main content Displays information in a two-column grid (1.6fr to 0.7fr) using tables, info cards and a pull-quote, depending on the page.
Journey timeline Links directly to sections within the current page only - it is a page-local table of contents, not site-wide navigation, and stays sticky in the viewport as the main column scrolls past it.
Footer Provides a second copy of the main navigation plus photography and font credits, so the acknowledgements are reachable from any page without scrolling back up.

Below the 700px breakpoint, the two-column grid collapses to a single column: the sidebar timeline drops out of its sticky position and simply appears after the main content in source order, which keeps the reading order sensible on small screens.

03. CSS Styles Used

Every style lives in websystems.css, with no embedded style attributes and no @import. The selectors fall into a few different categories, shown below with one representative example of each:

Selector Type Purpose
* Universal Resets box-sizing to border-box everywhere, so padding and borders don't inflate element widths.
body Element (type) Sets the general font, text colour and background for the whole page.
.navbar Class Arranges and positions navigation links; also made sticky to the top of the viewport.
.cover Class Controls the page cover layout (a CSS grid on Home, reused with extra classes on sub-pages).
#cover-name ID Styles the one-off main name heading on Home - an ID rather than a class because it only ever appears once.
.content, .past-content … Class (grouped) A comma-separated selector list applies the same two-column grid rules to several page-specific container classes at once, avoiding repeated CSS.
section[id], h2[id] Attribute Targets sections and headings that have an id attribute, adding scroll offset so jump-links don't hide under the sticky navbar.
.timeline-item:hover .dot Descendant + pseudo-class Selects the .dot span only when its parent timeline link is hovered, changing its colour.
.timeline::before Pseudo-element Generates the vertical connecting line down the timeline without needing an extra HTML element.
@media (max-width: 700px) Media query Switches the layout to a single column and reduces font sizes on small screens.

04. Graphic Design

This is a reflective, personal portfolio rather than a technical dashboard, so I chose a warm, low-contrast palette instead of a typical bright "tech" blue - cream and beige read as calm paper and tea-stained notebook pages, which fits the "journal of a journey" idea the site is built around. I kept the palette small on purpose, using four main colours supported by a few muted shades and neutral tones. This creates a consistent appearance without introducing too many unrelated colours.

Colour Code Use
Cream #FAF6EA Main background
Beige #E8DCC5 Cover and footer
Brown #463D35 Main text
Terracotta #C58B70 Highlights and hover effects

Typography

I paired one readable serif for everything a visitor actually has to read with two decorative display fonts used sparingly, so the personality comes through without hurting legibility:

  • Libre Baskerville: Used for the main body text, navigation, section headings and most other content, providing a consistent and readable serif typeface.
  • Better Together: Used mainly for the large page titles and the footer name "Phuong Linh", adding a decorative personal touch.
  • Simple Handmade: Used for the short subtitles beneath the page titles and the footer phrase "A place of memory", creating a handwritten accent.

Layout

  • A two-column grid (roughly 70% content, 30% sidebar) on every page, echoing a magazine or blog layout where a sticky sidebar keeps navigation in view beside longer reading content.
  • Large, muted section numbers ("01.", "02." …) repeated on every page as a consistent visual rhythm, so a visitor recognises the pattern after the first page even before reading the heading.
  • Sticky navigation bar and sticky journey sidebar, so the two most useful links - "go to another page" and "jump to a section" - are always within reach while scrolling.
  • A single 700px breakpoint collapses both the page grid and the footer grid to one column, keeping line lengths readable on phones instead of shrinking text to fit a layout built for desktop.

05. Alternative Text and CSS Accessibility

The website uses HTML and CSS features to make its content easier to understand and navigate, both for assistive technology and for visitors browsing with styles turned off.

Alternative text

Every <img> has a descriptive alt attribute rather than a filename or a generic word like "photo". For example, the home page photo uses alt="A picture of me Photo by Thien Truc", while the timeline photo on the Comments page uses alt="A photograph accompanying the website reflection. Photo by Thien Truc". Each description is specific to what that particular image is doing on that particular page, so a screen reader announces something meaningful rather than the same generic phrase four times. None of the images are purely decorative, so none use an empty alt="".

Browsing with CSS disabled

I tested the site in Firefox with "Use Style Sheets" switched off. Because the HTML is written in semantic source order - navigation, cover heading, main content, sidebar and footer - the page still reads top to bottom in a sensible order even with every grid, flex and sticky position rule gone:

  • The navbar, cover heading, main text, journey links and footer all still appear, just stacked as plain block elements instead of a styled grid.
  • Every link still works, because navigation relies on real <a href="..."> elements, not styled <div>s or JavaScript click handlers.
  • Tables and lists keep their structure (rows, cells, bullet markers) from the browser's default HTML rendering, so the learning-stage table on My Past and the colour table on this page are still readable without the custom table styling.
  • No information is carried by colour alone - the colour swatches in the table above are followed by the colour's name in text ("Cream", "Beige" …), so the table still makes sense in greyscale or with CSS off.
  • What is lost is purely decorative: the warm background colours, the two display fonts, the sticky behaviour of the navbar and timeline, and the section-number styling. None of that loss affects whether the content can be read or navigated.

Semantic HTML and responsive design

  • Semantic HTML: Elements such as nav, header, main, section, aside and footer organise the content, which is what lets a screen reader list the page's landmarks and lets the "CSS disabled" fallback above stay in a logical order.
  • Responsive design: A single @media (max-width: 700px) query reduces font sizes and collapses the two-column grids to one column, so the site stays usable on a phone without a separate mobile layout.
